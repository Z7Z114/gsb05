# filecrypt

`filecrypt` 是一个用 Java 写的流式文件加解密命令行工具：把任意大小的文件
用 AES-256-GCM 加密成一个自描述的密文容器，再用同一把密钥解回来。

## 构建

只要 JDK 17 及以上，不需要任何构建工具或第三方依赖：

```sh
javac -encoding UTF-8 -d out fcrypt/*.java
```

## 用法

```sh
filecrypt genkey  <key-file>
filecrypt encrypt --key <key-file> --in <in>  --out <out> [--force]
filecrypt decrypt --key <key-file> --in <in>  --out <out> [--force]
```

- `genkey` 生成一把 32 字节的原始随机密钥。
- `--in` 是要处理的文件，`--out` 是结果文件；`--force` 允许覆盖已经存在的
  `--out`（不加则拒绝覆盖）。
- 密钥文件必须恰好 32 字节（原始二进制，不是 hex / base64）。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 2 | 用法或环境错误（参数不对、密钥长度不对、输入不可读、`--out` 已存在且没给 `--force`、输出目录不存在……） |
| 3 | 认证失败：密钥不对、密文被改过、被截断、末尾有多余数据 |
| 4 | 不是本工具的密文（magic 不对，或文件短于 8 字节 magic） |

## 密文容器格式（必须与下述布局逐字节一致）

```
偏移 0    8 字节   magic，ASCII "FCRYPT01"
偏移 8    8 字节   本次加密随机生成的 salt
之后是若干条记录，首尾相接，无对齐填充：
  4 字节   大端整数 L：紧随其后的「密文 + tag」字节数（= 该记录明文长度 + 16）
  1 字节   记录标志位
  L 字节   密文 + 16 字节 GCM tag
```

- 明文按每块最多 1 MiB 切成若干记录（每条记录另有 16 字节 tag），
  最后一条记录是"收尾记录"：明文长度可以是 0（此时 L = 16），标志位带 `FLAG_FINAL`。
- 标志位当前只有 `FLAG_FINAL = 1` 这一个 bit 有意义，其余 bit 必须为 0。
- 空文件也必须产出合法容器：magic + salt + 一条明文长度为 0 的收尾记录。

## 行为规格

1. `genkey` 只接受一个输出路径；目标已存在时拒绝覆盖（退出码 2）。
2. 密钥文件长度不等于 32 字节时，退出码 2，且不产生任何输出文件。
3. `--in` 与 `--out` 指向同一个文件（含硬链接、`..`、大小写等不同写法）时，
   拒绝执行，退出码 2。
4. `--out` 已存在且未给 `--force`：退出码 2，原有文件保持不变。
   给了 `--force`：正常覆盖。
5. `--out` 所在目录不存在：退出码 2。
6. 加密：每次加密都用新的随机 salt，因此同一明文 + 同一密钥两次加密的
   密文必须不同；同一文件内，明文相同的两条记录也不得使用相同的密钥流。
7. 解密：`--in` 前 8 字节不是 `FCRYPT01`，或者整个输入不足 8 字节，
   退出码 4。
8. 解密：密钥错误、密文任意一个字节被篡改、或文件被截断，退出码 3，
   且**不得留下任何输出文件**。
9. 解密：**必须**能检出在记录边界上的截断（即恰好丢掉最后一条收尾记录、
   剩下部分看起来完全合法的情况），退出码 3。
10. 解密：收尾记录之后如果还有多余字节，视为被篡改，退出码 3。
11. 每条记录的认证必须把"这是流里的第几条记录"绑进去：调换两条同长度记录
    的位置、或把某条记录复制一份插回去，都必须被检出，退出码 3。
12. 输出通过临时文件 + 原子改名落盘：处理中途失败时，`--out` 不能出现
    半成品；且不得残留临时文件（形如 `.fcrypt-*.tmp`）。
13. 任何路径都不得把密钥内容写到标准输出或标准错误。
14. 大文件必须是流式的：不得把整个输入读进内存。

## 变更说明

本次修复对照「行为规格」逐条核查，共修复四类问题，容器字节布局
（magic、salt、记录头、tag、标志位）保持不变——IV 与 AAD 都是派生值，
不落盘，因此修正它们不需要改动格式：

1. **记录与流中位置未绑定**（对应规格 6、11）
   根因：`iv()` 里写的是 `putInt(0)`，记录序号被丢弃，同一容器内所有记录
   共用同一个 IV；`aad()` 也只绑了收尾标志、没绑序号。于是交换两条同长度
   记录、复制一条记录插回去、删掉中间一条记录，GCM 校验都能通过。
   修法：IV 恢复为设计中的 `salt(8) || 大端记录序号(4)`，AAD 改为
   `大端记录序号(8) || 标志位(1)`，加解密两侧一致。任何重排、复制、删除
   都会让 tag 校验失败（退出码 3）；同时同一文件内明文相同的两条记录
   也不再共用密钥流。
2. **记录边界上的截断被当成正常结束**（对应规格 8、9）
   根因：解密循环里读到 EOF 就直接 `return`，不管有没有见过收尾记录。
   修法：在见到带 `FLAG_FINAL` 的记录之前遇到 EOF，一律抛
   `AuthException`（退出码 3）。
3. **收尾记录之后的多余字节未检出**（对应规格 10）
   根因：见到 `FLAG_FINAL` 就立刻返回，不看后面还有没有数据。
   修法：收尾记录之后必须恰好是 EOF，否则视为被篡改（退出码 3）。
4. **失败时残留临时文件**（对应规格 12）
   根因：`.fcrypt-*.tmp` 只在成功路径上删除，加解密抛异常时泄漏。
   修法：临时文件的删除放进 `try/finally`，任何失败路径都会清理；
   `--out` 仍然只在全部处理成功后经原子改名落盘，不会出现半成品。
